# BOM-BOM队 · 五页路演稿 · 约 3 分钟

演示统一使用虚构 AI BOX 物料、供应商和报价。现场访问 ModelScope 公开空间。网络不稳定时，播放截图与历史证据，不声称刚才现场完成了模型调用。

## 1 · 让采购方案经得起验收（0:00–0:25）

**页内要点**：BOM Pilot｜AI 硬件采购决策工作台。给定生产目标，从录入报价生成可复算的采购建议。

**口播**：“大家好，我们是 BOM-BOM队，带来的作品是 BOM Pilot。做 AI 硬件时，BOM 有单价还不够。库存、起订量和阶梯价格一变，原采购方案就可能失效。BOM Pilot 将采购目标落实为可复算的方案，验收不过也会把原因说清楚。”

## 2 · 从成本表进入采购决策（0:25–0:55）

**页内要点**：可复用的 BOM 和报价快照。逐行校验、批量计算、成本贡献和供应约束。

**口播**：“这里是 20 项物料、160 条报价的虚构 AI BOX 样本。单台是 2,982.40 元，10 台是 29,822.20 元。批量价格会随阶梯变化。算力模块在构成里占主要份额，方便采购先核对对成本影响最大的料号。”

**操作**：展示成本分析，看类别和主要成本物料两张图。

## 3 · Agent 会根据验收结果改方案（0:55–1:40）

**页内要点**：自然语言目标 → 模型选择工具 → Python 计算 → 独立验收 → 失败后重规划或说明缺口。

**口播**：“Agent 负责决定下一步，比如先查报价，还是先计算方案。金额、缺口和约束都由独立的 Python 工具给出。在历史真实 OpenDev 记录里，100 台订单的单供应商方案验收失败。模型读到结果后选择拆单并重新验收。供给从 80 增加到 160，但需求是 200，所以它报告仍缺 40。现场的快捷演示用本地流程复算同一个案子，历史日志提供真实模型重规划的证据。”

**操作**：用缺料场景展示两次验收和重规划轮次，并指出历史 OpenDev 证据的来源。

## 4 · 三个场景，三个可复核的结果（1:40–2:30）

**页内要点**：涨价后减少 3,468.00 元支出。缺货仍缺 40 个。降本 8% 未达成。

**口播**：
- “涨价案里，若维持原分配需要 33,902.20 元。切换受影响物料的供应商后为 30,434.20 元，少花 3,468 元，但比涨价前依然高 2.05%。锁定的 AI-004 分配保持不变，方案待人工审批。”
- “缺料案下，268,099.20 元只是已分配小计。缺 40 个就不能给出完整 BOM 采购成本。”
- “降本案的目标价约 27,436.42 元。现有约束下最低仍是 29,822.20 元，降幅 0%，未达成。”

## 5 · 给采购一个能复核的交付物（2:30–3:00）

**页内要点**：86 项测试通过。方案与原 BOM 分开。约束、日志和待审批事项可追溯。

**口播**：“评委可以点开公开工作台的三个快捷场景，也可以下载 Excel 看分配、缺口和验收。我们把可行方案交给人工审批，把不可行的原因留给下一轮决策。现场样本都是虚构快照，目前只针对已录入的报价，不执行采购。”

**如果被问到**：真实 OpenDev 调用需安全配置和用户授权。当前支持单层 BOM 和单币种，搜索有规模上限。没有实时供应商行情、工程兼容性验证或自动采购。
